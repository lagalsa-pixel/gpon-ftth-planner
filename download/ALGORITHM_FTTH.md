## I. Входные данные и границы проектирования

1. **Точка заказа** — координата (lat/lon) центра села + ожидаемое число
   домохозяйств (ДХ) из тендерных данных. Опционально: обрезанный кадр
   спутникового снимка заказчика (`crop_image`) и/или жёсткая граница
   (`bbox_lock` / `zone: radius`).
2. **OSM** — дороги + контуры зданий через `api.openstreetmap.org` (чанки
   ~2,1×2,1 км; Overpass в регионе недоступен). Кэш XML на диске.
3. **Спутниковая мозаика Google Satellite z18** (~0,38 м/px на 50° с.ш.;
   z19 — апскейл, ESRI z18 в регионе — заглушки). Геопривязка: запад/север
   bbox → пиксели, точный обратный Web Mercator z18 (валидация 0,2 м).
4. **Граница села (v3):** только здания (дороги в связности не участвуют);
   сетка 50 м; морфологическое замыкание ~100 м (мостит пробелы между
   кустами застройки); компоненты ≥15 зданий; центроид в пределах 65 %
   зонда; отсечение чужих поселений по имени (Nominatim reverse, кэш);
   отступ границы +300 м. Ручной override — `bbox_lock`.
5. **Граница НП для маршрутизации (v3 схемы D):** морфология застройки —
   диски 175 м вокруг каждого ДХ + замыкание 250 м, внешний контур.
   Дорожный граф маршрутизации обрезается границей: фидерные трассы
   физически не могут покинуть населённый пункт.

## II. Детекция домовладений

### II.1. Базовый слой (v1)
1. **OSM-здания в зоне села** — основной источник (в ВКО 95–105 % для
   компактных сёл). Зона: bbox либо фиксированный радиус от точки заказа.
2. **CV-суплемент** (HSV-маски цветов кровли + морфология; фильтры площади
   40–350 м², компактности, вытянутости) включается автоматически при
   дефиците OSM >15 %. Контекст-фильтры: кандидат ближе 75 м к дороге, не
   ближе 15 м к OSM-зданию, рядом (<90 м) другие объекты.
3. **Кластеризация усадеб:** все здания ближе 16 м — одна усадьба (двор).
4. **Фильтры ДХ:** главное здание ≥36 м², центр двора ≤60 м от дороги.
   Контроль: отклонение от заказа >25 % — сигнал проверить превью/VLM.

### II.2. Уточнение детекции (v3, критерии заказчика Task 46)

Различия ЦВЕТА крыш НЕ достаточно для сплита (пристройка тоже другого
цвета, но меньше и другой формы). Признаки двух владений: увеличенные
габариты, ограждение перпендикулярно фасаду ближе к его центру,
продолжающееся вглубь двора; общая кровля одинаковой формы.

- **A. Сплит сблокированных домов** (один OSM-полигон = два владения):
  bbox ≥165 м², длинная сторона ≥12,5 м, линия раздела только у ЦЕНТРА
  фасада (t = 0,38–0,62 по обеим осям), части ≥36 м².
  - **A1 «двухцветная пара»:** хроматический сплит (dE_ab ≥ 8,5 при
    dE ≥ 18, или нейтральная+окрашенная, или оттенки ≥25°) при СОПОСТАВИМЫХ
    частях (ratio ≥ 0,35 — анти-пристройка);
  - **A2 «одноцветная пара»:** геометрический центр-сплит — только при
    найденном шве/стыке кровель (градиент яркости на линии раздела
    покрывает ≥45 % среза) — CV-заместитель признака ограждения.
    Солнечный/теневой скат различаются яркостью L, но не хроматикой —
    не сплитится.
- **B. Сплит дворов:** усадьба с 2+ дом-размерными (≥60 м²) зданиями.
- **C. Многоэтажки:** `building=apartments` или `levels ≥ 3` (sane-проверка
  площади этажа 40–3500 м²); N квартир = min(эт × S/55 м²,
  эт × подъезды × 4), подъезды ≈ длинная сторона / 28 м; позиции квартир
  вдоль фасада.

## III. VLM-верификация кандидатов (Task 47, завершена)

Все кандидаты A/B/C (кроме area-only C в сёлах с уже превышением заказа)
проверяются VLM по кропам (контур + двор, отступ 35 м). Режим —
**SINGLE** (одиночные кропы; парные стеки отклонены: межсерийная
согласованность 0,65 < порога 0,90). Промпт требует JSON-вердикт:

```
n_properties      — число отдельных владений внутри контура
fence_perp_center — забор примыкает к фасаду ПЕРПЕНДИКУЛЯРНО, ближе к центру
fence_extends     — линия раздела продолжается вглубь двора
seam_visible      — виден стык двух крыш/стен по линии раздела
annex             — это дом с пристройкой меньшего размера
roof_same_shape   — части кровли одинаковой формы
apartment_block / residential / levels / entrances  — для кандидатов C
```

**Гейт применения сплита (52c_build_v2.py):**
- **A:** `n_properties ≥ 2` И НЕ (`annex` И НЕ `fence_perp_center`)
  И есть признак раздела (`fence_perp_center` ИЛИ `fence_extends`
  ИЛИ `seam_visible`). Пристройка (меньший прямоугольник) — не владение.
- **B:** `n_properties ≥ 2` → новые ДХ на крупных зданиях кластера
  (по убыванию площади, не более n−1).
- **C:** OSM-этажность (tier 1, детерминированно) ИЛИ VLM-вердикт
  `apartment_block` И `residential` (tier 2, с levels/entrances из вердикта).
- Кандидаты без вердиктов НЕ применяются (ждут квоту VLM) — консервативно.

**Валидация (ВБ, 86 меченых кандидатов):** recall подтверждённых сплитов
39/40 (98 %); признак «забор между частями» разделяет подтверждённые и
отклонённые случаи идеально (40/40 против 0/46).

## IV. Древовидная сеть села

1. **Дорожный граф OSM:** денсификация до 4 м, сварка общих узлов,
   клип границей НП.
2. **Привязка:** ЦУ и каждое ДХ снаппятся к ближайшему узлу графа
   (допуск 90 м; медиана в ВКО 17–21 м).
3. **MST терминалов** по метрике кратчайших путей по дорогам (Дейкстра
   от всех терминалов) → объединение путей → **SPT-дерево от ЦУ**
   (кратчайшие пути от корня по объединённому подграфу). Сеть всегда
   следует улицам.
4. **Муфты:** (а) слияние точек подключения в радиусе 50 м по пути к ЦУ;
   (б) ВСЕ узлы ветвления дерева (степень ≥3); (в) дедупликация муфт
   ближе 15 м по дереву; (г) промежуточные муфты через ~100 м при
   дропе >120 м (укорачивание дропов — лучшая практика: короткий дроп
   50–75 м лучше длинного 150–200 м).
5. **Дропы:** от обслуживающей муфты вдоль улицы + ломаная по двору/фасаду
   (изломы детерминированы хэшем id ДХ; не по прямой).
6. **Магистраль** = объединение путей муфта→ЦУ.
7. **Обновление сетей после сплитов (53):** дерево не меняется; новые ДХ
   подключаются дропами к муфтам родителей; родительские точки
   смещаются к своей части крыши/фасаду; многоэтажки без ДХ-родителя
   рядом (>40 м) и здания вне кадра заказчика не подключаются.

## V. Топология схемы D (зонные ОРШ, единый OLT)

1. **Зоны:** дерево села режется жадными врезами по максимальной
   маржинальной экономии волокно-км (точный пересчёт полной раскладки на
   каждом шаге). Параметры: `MIN_ZONE = 48` ДХ (заполнение сплиттера
   1:64 ≥ 75 %), порог окупаемости доп. шкафа `S_MIN = 15` волокно-км.
2. **Точка стояния зонного ОРШ** — точный минимизатор стоимости
   `cost(v) = g(v) + ff_z × D(v)`, где g(v) — распределительные волокна
   зоны при корне в v (DP переноса корня), ff_z — фидерные волокна зоны,
   D(v) — кратчайший путь ЦУ→v. Состав зоны не меняется — перемещается
   только шкаф (ОРШ ближе к центру сектора, указание заказчика).
3. **Фидер ЦУ→зонный ОРШ** = ceil(1,25 × сплиттеры зоны) волокон,
   прокладывается по КРАТЧАЙШЕМУ пути дорожного графа (Дейкстра), в
   границе НП. На участках, общих с деревом, фидерные волокна едут в
   одном кабеле с распределительными; вне дерева — отдельный кабель
   ≥8 волокон (проходит муфты без сварок — сварки только на концах).
4. **Ёмкости кабелей:** F = max(8, ceil(1,25 × поток)); разложение по
   стандартному ряду 8/12/16/24/32/48/64/72/96 волокон (параллельные
   кабели).
5. **Кроссы:** ЦУ 144–1152 портов (ряд [144, 288, 576, 864, 1152]);
   зонные ОРШ (уличные шкафы) 48–576 (ряд [48, 96, 144, 288, 576]);
   порты = ДХ × 1,1.
6. **Схема A (централизованная, сравнительная):** сплиттеры 1:64 в ЦУ,
   выделенное волокно каждому ДХ. Без врезов D точно воспроизводит A
   (инвариант самопроверки).
7. **Инварианты:** ДХ/дропы/трасса A = D; сумма домов зон = ДХ села.

## VI. Ведомость материалов (BoQ)

- Сплиттеры: PLC 1:64 (равномерное деление; FBT 1:2 только для
  шинных топологий — не применяется). Кол-во = ceil(ДХ зоны / 64) на
  зону (суммарно в проекте ВКО: 58 шт на 2765 ДХ, заполнение 74,5 %).
- ОРШ: 1 ЦУ + зонные на село; OLT-порты = числу сплиттеров.
- Муфты: узлы ветвления + переходы ёмкости; транзитные волокна проходят
  без сращивания.
- Сварки: (2×ДХ + 2×сплиттеры) × 1,1; КДЗС = сваркам; пигтейли =
  ДХ + 2×сплиттеры; коннекторы — SC/APC (3 разъёма на линию: ODF ЦУ,
  кросс ОРШ, ONT — учитываются в бюджете §VII).
- Расходники подвесной прокладки (воздушная по ЛЭП 0,4 кВ — базовый
  вариант для сёл): подвесы 30/км, анкеры 2/ДХ, крепёж 6/ДХ.
- Запасы: магистральный кабель +10 % (закуп.), дроп-кабель +5 %,
  расходники +10 %.
- Межселённый транспорт до ЦУ и активное оборудование — за рамками BoQ.

## VII. Оптический бюджет (НОВОЕ v1.1)

**Основание:** foxes-com («расчёты затухания — для линии до самого
удалённого абонента; сумма потерь = энергетический бюджет; учитывать
эксплуатационный запас»), prorostelecom («самый ответственный момент в
проектировании PON/GPON — расчёт оптического бюджета потерь»), begemot
(расчёт бюджета с учётом специфики ИЖС). В v1.0 отсутствовал — добавлен.

**Линия (восходящий поток 1310 нм — максимум потерь):**
OLT(ЦУ) → ODF → фидер ЦУ→ОРШ → кросс ОРШ → сплиттер PLC 1:64 →
распределение ОРШ→муфта → муфта → дроп → ONT.

**Формула (худший абонент зоны, верхние оценки):**

```
A = 0.35×L + 21.0 + 3×0.5 + (2 + n_транз + 2)×0.1 + 0.2,   дБ
    │       │      │         │                └ штрафные потери (изгибы)
    │       │      │         └ сварки: концы фидера(2) + транзитные муфты + дроп(2)
    │       │      └ разъёмы SC/APC: ODF ЦУ + кросс ОРШ + ONT
    │       └ сплиттер PLC 1:64 (верхняя граница спецификации)
    └ волокно G.652D @1310 нм (upstream, худший поток)
L = фидер(root_dist_m) + max путь дерева ОРШ→муфта + max дроп села
```

**Нормативы:** Class B+ = 28 дБ (рабочий бюджет GPON); Class C+ = 32 дБ
(опция для дальних зон); эксплуатационный запас ≥ 3,0 дБ.

**Гейты:**
- `A + 3 ≤ 28` — зона «ok»: полная годность, оптика B+;
- `A ≤ 28` — зона «ok-hard»: годно, но запас < 3 дБ → для дальних
  PON-портов зоны указывается оптика **Class C+** или сплиттер **1:32**
  (экономит 3 дБ);
- `A > 28` — «EXCEEDED»: редизайн зоны (сдвиг ОРШ к центру / 1:32).

**Реализация:** `scripts/56_optical_budget.py` (проект ВКО),
стадия `boq` конвейера `ftth_pipeline.py` v2.4 (поле `optical_budget`
в boq.json, вывод худшей линии на село), QA-гейт `budget` в стадии `qa`.

**Валидация на выпущенном проекте ВКО (v4, network_hh2, 2765 ДХ):**
все 34 зоны в бюджете Class B+; худшая линия — Верхнеберезовка, зона 3:
A = 27,42 дБ (маржа 0,58 дБ; фидер 1359 м + распределение 1990 м +
дроп 133 м, 31 транзитная сварка); 14 зон «ok» с полным запасом,
20 зон «ok-hard» → рекомендация C+/1:32 для дальних портов. Превышений
нет — редизайн не требуется.

| Измерительный контроль: OTDR (фидер ЦУ→ОРШ) + источник/мощемер (ОРШ→абонент) [5] | Внесено в §X как этап контроля СМР (не влияет на BoQ) | ✎ документировано |
| Коннекторы LC/APC или SC/APC [1] | SC/APC — зафиксировано (3 разъёма на линию в бюджете) | ✔ формализовано |
| Исходные данные: адресный план, % охвата, технология, бюджет, схема сплиттеров, ёмкости кабелей [1] | Точка заказа + ДХ + кадр заказчика; технология GPON B+; схема D §V; ёмкости §V.4 | ✔ соответствие |
| Гибкость подключений в существующем жилье: кросс в ОРШ, паркинг пигтейлей, документирование [3] | Кроссовые поля ОРШ 48–576 портов (×1,1 запас) | ✔ соответствие |
| Дилемма «частые муфты малой ёмкости vs длинные дропы» [3] | Сбалансировано: слияние 50 м + промежуточные 100 м + ветвления | ✔ соответствие |

**Вывод сверки:** архитектура схемы D полностью соответствует отраслевой
методологии; единственное содержательное упущение v1.0 — отсутствие
расчёта оптического бюджета — устранено в v1.1 (§VII). Редизайн
выпущенного проекта не требуется (все зоны в B+).

## X. Подключение нового населённого пункта

**Конвейер:** `download/ftth_pipeline/` (v2.4) — переиспользуемый
инструмент, проверенный двумя тестами (точное воспроизведение эталона
ВКО; полное новое село Бобровка, 817 ДХ).

1. **Конфиг:** добавить село в `config.json` — `num`, `key`, `name`,
   `lat/lon` (точка заказа), `hh` (число ДХ заказа), `radius_m`,
   `zone` (bbox/radius), `cv_supplement: auto`, при необходимости
   `crop_image` (кадр заказчика), `bbox_lock`, `force_anchor`.
2. **Стадии** (каждая идемпотентна, кэш внешних запросов):
   `fetch → households → anchor → network → [crop] → boq → map --vlm →
   xlsx → qa`.
3. **Точки контроля человеком** (осознанные решения, не баги):
   - после `fetch` — граница села (превью мозаики; `bbox_lock`);
   - после `households` — детекция vs заказ (превью; порог ±25 %);
   - после `anchor` — кандидат ЦУ №1 (превью; `force_anchor`);
   - после `map` — зоны/легенда/подписи (превью; `--vlm`).
4. **VLM-верификация кандидатов A/B/C** (при наличии квоты z-ai):
   оркестратор `scripts/52b_call_t47.sh` — кропы кандидатов → одиночные
   VLM-вызовы (темп 3/мин: `VLM_INT=20000 VLM_CONC=1`) → вердикты
   JSON → гейт §III → пересборка 52c → 53 → 54 → выдача (47_final_chain).
5. **Критерии готовности:** QA — все проверки пройдены; отклонение ДХ
   в допуске или задокументировано (пример: Алтайский −47 % — лот шире
   кадра спутника); оптический бюджет — без превышений B+ (зоны ok-hard
   получают рекомендацию C+/1:32).
6. **Особые случаи:** линейное село у города — `zone: radius`;
   село, слившееся с соседним — `zone: radius`; кадр заказчика — стадия
   `crop` (SIFT+FLANN+RANSAC привязка, сеть в границах кадра).

## XI. Ограничения и допущения

- Межселённый транспорт до ЦУ и активное оборудование (OLT, ONT) — за
  рамками BoQ (как в проекте ВКО).
- Волокно-км схемы A считается справочно (выделенное волокно каждому ДХ).
- Мозаики ~150 Мп требуют 2–3 ГБ ОЗУ на рендер.
- Кадр заказчика должен быть неповернут (|rot| < 0,5°).
- Бюджет §VII считается по верхним оценкам (max дроп села на каждую зону,
  путь дерева от узла вреза) — фактические линии короче расчётных.
- VLM-проверки опциональны; без них A/B-сплиты не применяются
  (консервативно), многоэтажки — только по OSM-этажности (tier 1).
